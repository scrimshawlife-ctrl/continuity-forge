# Kubrick Esoteric and Alchemical Encoding Lexicon

Status: **PROPOSED reference substrate**  
Scope: hidden narrative, cinematic, sonic, spatial, material, temporal, and continuity encoding  
Surface rule: encode through dramatic function and formal constraint; do not default to explicit occult exposition or decorative iconography.

## Governing law

> Esoteric structure is valid only when it changes dramatic pressure, perception, causality, relation, transformation, recurrence, or material state.

Every use must preserve the existing Kubrick requirements:

1. observed form before interpretation;
2. dramatic function before attribution;
3. mutation on recurrence;
4. provenance and tradition boundaries;
5. no one-to-one symbolism;
6. no occult collage;
7. no symbolism that compromises agency, causality, clarity, tone, or production feasibility;
8. all outputs remain PROPOSED until accepted by Continuity Forge.

## Encoding vectors

Use one or more of these vectors rather than literal explanation:

- framing and center ownership;
- blocking, distance, occlusion, threshold access;
- camera motion, lens behavior, shot duration, edit cadence;
- color progression, material change, light behavior;
- sound placement, rhythm, drone, silence, leitmotif mutation;
- prop ownership, damage, repair, persistence, disappearance;
- costume, gait, gesture, posture, vocal register;
- architecture, geometry, negative space, directionality;
- recurrence, inversion, convergence, residue;
- causal state, knowledge state, relationship state, identity state;
- scene order, count, phase, compression, expansion, return.

## Selection protocol

Do not use the lexicon as a theme vending machine. Select concepts deterministically.

```yaml
esoteric_selection:
  dramatic_problem: string
  observed_scene_state: string
  desired_state_change: string
  selected_concepts:
    - concept_id: string
      tradition: string
      dramatic_function: string
      encoding_vectors: [string]
      observable_evidence: [string]
      mutation_rule: string
      inversion_condition: string | null
      payoff_condition: string | null
      residue: string | null
      audience_visibility: peripheral | readable | foreground | delayed
      confidence: 0.0-1.0
      provenance: [string]
      tradition_boundary: string
  rejected_concepts:
    - concept_id: string
      reason: string
  canon_status: PROPOSED | LOCKED
```

## Density limits

Default limits unless a project explicitly establishes a denser grammar:

- one governing transformation grammar per sequence;
- one primary and at most two secondary concepts per scene;
- no more than two channels communicating the same relation simultaneously;
- one explicit cross-tradition bridge only when provenance and narrative justification exist;
- every repeated concept must mutate in form, ownership, context, consequence, scale, rhythm, or valence;
- absence may count as mutation when previously established presence makes it legible.

## Failure states

Flag and stop symbolic expansion when any of these occur:

- concept chosen only because it sounds occult;
- literal iconography substitutes for dramatic function;
- multiple traditions are flattened into visual similarity;
- a number, color, geometry, planet, element, or card is assigned fixed meaning without project-local evidence;
- symbolic design removes character agency or obscures basic causality;
- the scene requires explanatory dialogue to make the system work;
- interpretation confidence exceeds available evidence;
- continuity state is altered without Forge mutation authorization;
- generated variants diverge from identity, prop, location, or style invariants.

When evidence is insufficient, return `NOT_COMPUTABLE` rather than inventing correspondence.

## Minimal operational loop

```text
OBSERVE scene state
-> DEFINE dramatic change
-> SELECT one governing concept
-> MAP to cinematic vectors
-> SPECIFY recurrence mutation
-> CHECK tradition boundary
-> RUN anti-slop gates M-W
-> EMIT symbolic_architecture as PROPOSED
-> HAND OFF to Continuity Forge for canonical acceptance
```
